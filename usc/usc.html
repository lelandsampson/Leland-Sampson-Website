This presentation introduces web content management systems through a library and information-science lens. The central argument is that a CMS is not merely a publishing tool: it also shapes governance, user experience, accessibility, participation, and long-term sustainability.

Why a content management system?

  • Information changes constantly.
  • Static sites are not interactive.
  • Static sites quickly become unmanageable.

Takeaway: A library website is an ongoing organizational system.

The challenge is not simply putting information online. Libraries must keep information accurate, organized, accessible, and useful while many people contribute to the site.

What is a web content management system?

A CMS coordinates:

  • Content
  • People
  • Workflows
  • Presentation

Definition: A system for creating, organizing, publishing, and maintaining web content.

A CMS manages web content, but it is not necessarily the website’s visual design, online catalog, or entire digital ecosystem. This distinction follows Barker’s discussion of what content management is and is not.

A CMS is not the same as

  • a library website.
  • an online catalog.
  • a discovery interface.

One ecosystem, different functions.

The CMS is part of a larger information environment. A library website may link to or embed catalogs, discovery tools, databases, event systems, and social media, but these systems should not be treated as interchangeable.

One ecosystem, different functions

System Main job
CMS Manage web content
Website Explain how to use library
Catalog Find library materials
Discovery interface Search across resources

These systems may be linked or integrated, but they solve different problems.

What users actually experience

Users do not see the CMS. They see:

  • Navigation
  • Page structure
  • Content

A good user interface distills complex systems into a simple, intuitive experience

Content structure and governance are user-experience issues. If content owners use inconsistent labels, duplicate information, or unclear categories, users experience that internal complexity as confusion.

Responsive design

Content should adapt to:

  • Phones
  • Tablets
  • Desktops

Goal: Preserve clarity while the layout changes.

Bento-box interfaces

Distinct panels can organize different user needs:

  • Search
  • Physical location info
  • Events
  • Research help

Purpose: Visual grouping should speed navigation.

Accessibility is part of design

Concept Question
Usability Can people use it easily?
Accessibility Can people with disabilities use it?
Universal design Did we design for variation from the start?

Accessibility is a design and governance responsibility.

Accessible content in practice

  • Keyboard navigation
  • Color contrast
  • Alternative text
  • Captions and transcripts
  • Clear headings and links

An inclusive website anticipates different abilities, devices, languages, levels of technical experience, and ways of interacting with information. Accessibility should be built into content models, templates, workflows, and review practices.

Why organizations adopt a CMS

  • Distributed authoring
  • Consistent design
  • Faster updates
  • Reusable content
  • Easier maintenance

What a CMS cannot automatically solve

  • Content governance
  • Effective communication
  • Poor workflows
  • Training needs

A CMS reflects organizational values and priorities.
